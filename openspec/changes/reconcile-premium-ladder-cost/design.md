# Design: reconcile-premium-ladder-cost

## Доказательство расхождения (×3)

Один `pi_bench_out_task_*.ndjson` содержит ненулевой `usage`-блок ровно **3 раза** на
каждый ассистентский ответ (пример из `task_389_...`):

```
usage blocks: 228, из них ненулевых 18; уникальных значений — 6, каждое встречается 3×
{'input': 2443, 'output': 95, 'totalTokens': 2538}   ×3
{'input': 2693, 'output': 859, ...}                  ×3
...
```

Старый `_extract_usage` обходил все вложенные поля рекурсивно, поэтому попадал на
тот же usage по нескольким путям графа (message_end + turn_end echo +
agent_end.messages[]). Отсюда точный множитель **3.000** и по input, и по output у
всех моделей.

## Сверка (ключ `kap-hermes`, окно лестницы)

Источник истины по ₽ — дедуплицированный экспорт активности провайдера
(колонка `cost`, ₽). Сырые токены раннера завышены ×3 (раздел «Доказательство»),
поэтому строки перепубликуются по токенам и ₽ провайдера.

| модель | published tokens | provider tokens | × tokens | provider ₽ | published ₽ |
|---|---:|---:|---:|---:|---:|
| sonnet-4.5 | 4 526 346 | 1 508 795 | 3.000 | 1 060.50 | 1 195.29 |
| sonnet-4.6 | 2 439 192 | 813 109 | 3.000 | 652.95 | 697.40 |
| opus-5.5 | 1 785 909 | 595 335 | 3.000 | 556.35 | 499.04 |
| opus-4.8 | 2 155 722 | 718 602 | 3.000 | 764.49 | 583.77 |
| fable-5.1 | 1 932 366 | 644 155 | 3.000 | 1 485.05 | 535.36 |
| fable-5 | 1 665 021 | 549 550 | 3.030 | 1 263.14 | 460.57 |
| **Итого** | 14 504 556 | 4 829 546 | **3.00** | **5 782.48** | 3 971.43 |

Целевой провайдерский итог — **5 782 ₽** (цель перепубликации). Колонка
`published` фиксирует состояние до исправления: токены ×3, а ₽ — результат
частичной более ранней переоценки, поэтому она не согласована с биллингом.
Перепубликованные строки берут `provider tokens` и `provider ₽`.

sonnet-5 / sonnet-5.5: **0 строк** в биллинге (403 «model not available»), списаний нет.

## Источник истины по ₽

- Факт списаний — экспорт активности Cloud.ru (колонка `cost`, ₽), а не токены раннера.
- Допуск сверки: |published − provider| / provider ≤ 2% при single-count-раннере.
- Дедуп обязателен: два экспорта могут полностью перекрываться по окну.

## Решение

1. Считать per-model tokens/₽ из дедуплицированного экспорта (`kap-hermes`).
2. Перегенерировать форк-строки/страницы, сохранив pass-рейтинг.
3. Обновляемость: `scripts/reconcile_ladder_billing.py` воспроизводит сайдкар при
   повторном запуске (idempotent), `--check` не должен менять выход.

## Реализация: data override (без перепрогонов)

Перегенерация строк лестницы **не требует** повторного запуска Pi-раннера:
провайдерский экспорт даёт фактические tokens/₽ напрямую, поэтому исправление
вносится как *data override*.

1. `scripts/reconcile_ladder_billing.py` (idempotent) читает облачные экспорты
   активности, дедуплицирует по `(date, api_key, model, input_tokens,
   output_tokens, cost)`, фильтрует `--key kap-hermes` и пишет по одному
   сайдкару на прогон: `results/reconciled/pi_shotlist_<token>_20261114.json`
   с `{model, input_tokens, output_tokens, cost_rub}`.
2. `scripts/fork_ladder_override.py` подхватывает сайдкары по stem прогона.
3. `scripts/build_fork_results.py` и `scripts/build_fork_home.py` применяют
   override в момент чтения `summary`: `total_tokens = input + output`,
   `estimated_cost_rub = cost_rub`. Pass-рейтинг, время и шаги берутся из
   `summary` без изменений.
4. Страницы перегенерируются штатно:
   `build_fork_results.py` → `build_fork_pages.py` → `build_fork_home.py`.

Сырые run-артефакты `results/pi_shotlist_*_20261114.json` не правятся — override
живёт отдельным слоем, поэтому его легко перепроверить и откатить
(удалить `results/reconciled/`).

## Дедупликация (проверка)

Два предоставленных экспорта (`bill_old.csv`, `bill_new.csv`) полностью
перекрываются в окне лестницы, поэтому дедуп обязателен:

- всего строк в двух файлах: 22 861;
- строк ключа `kap-hermes`: 2 688 → после дедупа 1 344;
- сумма `cost` по дедупу: **5 782.48 ₽** (≈5 782 ₽) — совпадает с ожиданием.

Per-model (дедуп, `kap-hermes`): sonnet-4.5 = 1 060.50, sonnet-4.6 = 652.95,
opus-5.5 = 556.35, opus-4.8 = 764.49, fable-5.1 = 1 485.05, fable-5 = 1 263.14 ₽.

## Порядок действий при будущем расхождении

1. Выгрузить дедуплицированный экспорт активности за окно волны по рабочему ключу.
2. `python3 scripts/reconcile_ladder_billing.py <csv...> --key <key>` — обновит
   сайдкары и напечатает diff «published vs provider».
3. Если |published − provider| / provider > 2% — перегенерировать страницы
   (`build_fork_results.py`, `build_fork_pages.py`, `build_fork_home.py`) и
   закоммитить; pass-рейтинги не трогать.
4. `python3 scripts/reconcile_ladder_billing.py --check` и
   `python3 scripts/build_fork_results.py --check` должны выходить с кодом 0.
