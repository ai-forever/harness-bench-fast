# Design: add-fork-table-ranks-and-sorting

Изменение целиком живёт в генераторе `scripts/build_fork_home.py` (страницы
`docs/fork.html` / `docs/fork.en.html`). Данные, схема колонок и i18n не меняются.

## Колонка места (`#`)

- В разметку заголовка добавляется первая ячейка
  `<th scope="col" class="numeric place">#</th>`; это делается в обеих шапках —
  `HEAD` (Shot List / Light / Medium) и `SAMPLE_HEAD` (Medium sample).
- Каждая строка данных получает первой ячейку `<td class="numeric place">{i}</td>`,
  где `i` — порядковый номер из `enumerate(rows, 1)` в `_rows_html()` /
  `_sample_rows_html()`. Групповые строки (`<tr class="group"><td colspan=…>`) остаются
  без колонки места.
- «Непрерывность сквозь группы» обеспечивает клиентский пересчёт: функция
  `numDataRows(table)` в инлайн-скрипте проходит по строкам `tbody` в текущем DOM-порядке,
  пропускает `tr.group` и переназначает `td.place` = 1,2,3… Это одновременно и
  инициализация при загрузке, и пересчёт после каждой сортировки (серверный `i` стартует
  заново в каждой из групп `_rows_html`, поэтому клиент выравнивает нумерацию в единую
  последовательность).
- Стиль `td.place{opacity:.6;font-variant-numeric:tabular-nums}` даёт моноширинные цифры.

## Сортировка

- Заголовки сортируемых колонок помечаются `class="sortable"` и атрибутом
  `data-sort`, задающим тип разбора значения: `number`, `ratio` или `text`. Первая
  колонка `#` — без `data-sort` (несортируемая).
- Клиентский обработчик (инлайн `<script>`, IIFE) навешивается на все
  `table.leaderboard-table`:
  - `sortTable(table, idx, type, dir)` собирает строки `tbody`, разбивая их на сегменты по
    групповым строкам (`tr.group` — граница сегмента). Каждый сегмент сортируется
    отдельно, заново собирается в единый список, после чего строки переставляются через
    `tbody.appendChild`. Групповые строки остаются на своих местах — они не участвуют в
    сортировке, но служат разделителями.
  - клик по заголовку: `dir` переключается `asc` ⇄ `desc`, активному `th` ставятся классы
    `asc`/`desc` (стрелка через CSS-псевдоэлемент `::after`), с остальных заголовков
    состояние снимается.
  - после сортировки вызывается `numDataRows(table)` — номера места пересчитываются под
    новый порядок.
- Порядок «отсутствующие в конце» обеспечивается компаратором: `null`-значения (источник —
  `parseVal`, вернувший `null`) всегда сравниваются «больше» числа/строки
  (`if(va===null) return 1; if(vb===null) return -1;`), независимо от `dir`.

## Правила разбора значений (`parseVal`)

- `text` — `trim().toLocaleLowerCase()` (регистронезависимое сравнение строк).
- `ratio` — значение вида `X/Y` (`Result`, `Coverage`): обе части парсятся как числа
  (`replace(/[^0-9.,-]/g,'')`, запятая → точка), возвращается `a/b`; если знаменателя нет,
  но числитель есть — возвращается `a`; иначе `null`.
- `number` (по умолчанию, для `%`, `Time`, `Steps`, `Tokens (cost)`) — берётся первая
  числовая группа `/[0-9][0-9 .,]*/`, убираются пробелы-разделители тысяч, запятая →
  точка, затем `parseFloat`.
- Пустая строка, `—`, `-`, `–` → `null` (уезжает в конец).

## Почему клиентская сортировка

Страница статическая (GitHub Pages), данные уже целиком лежат в разметке. Клиентская
сортировка не требует регенерации, не ломает `--check` (HTML детерминирован) и работает
для всех наборов одним кодом. Серверный/URL-параметр сортировки осознанно вынесен в
out of scope.
