Руководство по выбору · форк

Что × чем × когда: выбор модели и харнесса

Практическое руководство по выбору харнесса × модели для задач harness-bench-fast, построенное только на уже выполненных прогонах. ₽ — факт биллинга провайдера там, где есть сайдкар reconciled, иначе оценка по тарифу; основание указано в столбце Basis.

Выводы (TL;DR)

  • Default-выбор для подавляющего большинства задач — DeepSeek-V4.1-Flash. На Shot List он даёт 100% (OpenClaw) / 98% (DeepSeek Harness) при стоимости порядка ~1 ₽ за решённую задачу.
  • Премиум-модели на текущих данных не окупаются. Лучший premium (Claude Sonnet 4.5, 98.1%) стоит ≈25× дороже равного по результату DeepSeek. Ни одной floor/boundary-задачи premium не закрывает — их берёт DeepSeek.
  • Харнесс влияет на результат не меньше модели: одна и та же модель на разных харнессах даёт разные score/время/шаги. Выбирайте пару (harness × model), а не «модель вообще».
  • Чего в данных нет: wave21 (hard-coupled) не измерен вовсе; long-волна покрыта лишь частично (6/20); Light-391 — 3 прогона. Такие клетки помечены unmeasured, а не «fail».

Как читать (по ситуациям)

  • shot-list — единственный плотно сравнимый бакет (4 харнесса, полный набор). Экшн: Default = DeepSeek-V4.1-Flash на OpenClaw или DeepSeek Harness.
  • medium-reflect / long-context / wave19-feasibility — DeepSeek остаётся на границе Парето; long-бакет измерен частично → решения с низкой уверенностью.
  • light-391 — сопоставимой пары «один харнесс» нет → только unmeasured.
  • hard-coupled (wave21) — не измерен вовсе → рекомендаций нет до прогонов.

Методология

  1. Источник — results/*.json; для премиум-лестницы ₽ из биллинга провайдера (results/reconciled/).
  2. Классификация — общий модуль scripts/fork_metadata.py (стемы совпадают с форк-таблицами).
  3. Фронт Парето — по pass_rate внутри одного набора (bucket × total); доминируемые → anti-patterns. Абсолютный passed — только для отображения x/y.
  4. Тиры — пер-бакет (терцили ₽/решённую задачу по полному набору), т.к. знаменатели разные.
  5. Правило «premium оправдан»: не доминируем и (≥ +3 п.п. pass или закрыта ≥1 floor/boundary-задача).
  6. Сравнение только внутри одной task-set версии; partial = unmeasured.
