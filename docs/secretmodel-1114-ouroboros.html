Token usage · last attempts only

At least 733,698,642 tokens: 728,551,298 input and 5,147,344 output. Reported cached input is 681,910,528 tokens, already included in input; five metered responses omit the cache breakdown. Reasoning is included in output, never added again. Repeated context is counted on each request; these are usage tokens, not unique text tokens or a monetary bill.

All 90 tasks have some recorded usage. Coverage is 2,749 of 2,955 physical requests; 21 tasks have complete request accounting and 69 are partial. The 206 unmetered requests comprise 168 HTTP errors, 34 HTTP 200 responses without usage, and four requests without a recorded HTTP status. Their consumption is unknown, not zero. Totals therefore remain a lower bound.

Only the last physical attempt of each task is counted; 47 earlier attempts are excluded. Within each retained attempt, all recorded model requests, including native workers and reviews, are counted once. For streamed responses, only the final cumulative usage snapshot is summed. Native hierarchical counters are not added on top of wire usage. No duplicate request files or response IDs were found.

Protocol and audit

Native pro profile, four native workers, required blocking reviews. Main reasoning effort: medium; reviewer effort: high. Output limit: 65,536 tokens. Concurrency increased from 2 to a limit of 16 tasks during the run; bubblewrap isolation; temperature was not overridden. Ordinary task guard: 3,600 seconds; long-context floor: 7,200 seconds; task-specific limits apply.

The published result retains the last physical attempt of every task, including failed outcomes, as directed by the benchmark owner. Native runtime results and host-recorded terminal submissions are distinguished from task-created result files. Host receipts were checked against their hashes, task identity, protocol fingerprint and deadline. Recovered transport errors do not invalidate an already completed task. Earlier attempts are excluded from both the score and token accounting; this is not best-of-N selection.

Scoring revisions, November 16: protocol errors count as harness failures in the full 90-task denominator. A subsequent owner instruction selects the last attempt for every rerun task, replacing the earlier first-completion policy.
