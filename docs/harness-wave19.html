Protocol and validation

Source 3796b9084093e5f9383077d7bde8f1ce1f0d57b5, Linux/bubblewrap, one attempt per task, hard 120-second task budget, max_tokens=16384. Eight total task slots; one active task per configuration in this matrix. Codex reuses 46 completed wave 19 task records from its interrupted full runs, without score-based selection; original runtime identity and task budgets were retained. No old tasks were rerun for this extension.

Native versions: Codex CLI 0.160.1, Claude Code 2.1.300, pi-mono 0.73.1, OpenClaw 2026.9.6 (eb377ac). Codex uses a Responses-to-Chat adapter; Claude Code uses a Messages-to-Chat adapter; pi-mono and OpenClaw use Chat Completions. Native tools and reasoning replay are retained; there is no SFT tool pruning or single-call restriction. Codex multi-agent/apps/hooks and web search were disabled. Claude uses isolated settings and no external MCP configuration; pi uses its historical offline/no-extension configuration. Client token-count estimates are approximate when requested. These are complete agent configurations, not model-only rankings.

Validation covered 40 unique current task IDs per configuration, frozen task/service protocol, unchanged retained records, native infrastructure counters and terminal API-error screening. Three Claude Code + Haiku attempts were infrastructure-invalid: an adapter placed user continuation before pending tool results, producing API 400. After fixing that order, only those three tasks were rerun; all three passed, changing 23/40 to 26/40. The other 37 outcomes were retained unchanged. Original attempts remain private. Final native infrastructure failures: zero. Model/task timeouts remain ordinary failures. This validation is not an exhaustive qualitative study of every failed solution.
